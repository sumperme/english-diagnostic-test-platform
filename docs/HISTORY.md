# EDT Platform — Migration History

Completed one-time rollouts, kept for the record. **Nothing on this page needs to be run
again.** It is here so that an unexpected symptom (old submissions reappearing, mixed score
ranges, missing audio after a database restore) can be traced back to the rollout that
produced today's data shape.

For the live publish and migration workflow, see [`PUBLISH_UI.md`](PUBLISH_UI.md).

---

## v4 — unified test bank in D1 (migrations `0006`–`0010`)

Version 4 moved the question banks out of frontend TypeScript files and into Cloudflare D1,
and added R2-backed listening audio plus server-rendered PDF reports.

| Migration | Effect |
| --------- | ------ |
| `0006_unified_test_bank.sql` | 12-table unified schema (`tests` → `test_parts` → `dimensions` / `shared_resources` → `question_groups` → `questions`, plus attempts and report tables) |
| `0007_seed_test1.sql` | Paper I content (90 groups) |
| `0008_seed_test2.sql` | Paper II content (45 groups, 6 passages, 20 audio resources) |
| `0009_voucher_test_usage.sql` | Per-test voucher usage tracking |
| `0010_activate_test2.sql` | Paper II set to `active` |

Rolling production onto v4 required, once:

```powershell
.\scripts\upload-assets.ps1        # Paper II MP3s + PDF fonts to R2
.\scripts\migrate-remote-db.ps1    # backup + apply 0006-0010 + cleanse old results
.\scripts\publish-ui.ps1           # push code; Workers Builds deploys
```

The cleanse step wiped submissions, sessions, and attempts and reset voucher usage; vouchers
and teacher credentials were kept. A pre-migration backup was written to `db_backup/`
automatically.

> Present-day equivalent: for additive rollouts, prefer
> `.\scripts\migrate-remote-db.ps1 -SkipCleanse` so live attempts survive. See
> [`PUBLISH_UI.md`](PUBLISH_UI.md).

## v3 — Paper I expanded to 90 questions (report version `3.0.0`)

Paper I grew from 72 to **90 questions**. Submissions recorded before that change use
incompatible dimension keys and score ranges, so historical `submissions` rows were cleared
once after deploying v3 to keep teacher percentiles and score buckets from mixing two
scoring models:

```powershell
npx wrangler d1 execute edt-diagnostic --remote -c wrangler.toml --command "DELETE FROM submissions;"
npx wrangler d1 execute edt-diagnostic --remote -c wrangler.toml --command "DELETE FROM sessions;"
```

Vouchers and teacher credentials were unaffected. This ran on production when `3.0.0` was
published and does not need repeating unless pre-v3 submissions reappear (for example after
restoring an old backup).

## Initial Cloudflare setup

All one-time platform setup is complete and is not repeated per deploy.

| Step | Task |
| ---- | ---- |
| 1 | Prerequisites (`npm install`, `npx wrangler login`) |
| 2 | GitHub repository connected to Cloudflare |
| 3 | D1 database created and its ID recorded in `wrangler.toml` |
| 4 | Remote migrations applied |
| 5 | Vouchers seeded from `Evouchers.txt` |
| 6 | Workers Builds configured on `main` |
| 7 | Cloudflare Access policy set to **Everyone** (the site is public) |
| 8 | `ALLOWED_ORIGIN` pointed at the production URL |
| 9 | React SPA and API served from one URL via the `ASSETS` binding |
| 10 | End-to-end smoke test |

The settings themselves, and what to do when one of them breaks, are documented in
[`PUBLISH_UI.md` → Appendix: initial setup and troubleshooting](PUBLISH_UI.md#appendix--initial-setup-and-troubleshooting).

## v5 — Paper I Oct 2026 bank, preset feedback and report rebuild (`0020`)

**Status: done on production, 16 Oct 2026.** Applied with `.\scripts\migrate-remote-db.ps1`
(full cleanse: all candidate attempts, reports, sessions and submissions removed; voucher usage
reset; vouchers and teacher credentials kept). Pre-migration backup:
`db_backup/edt-diagnostic-20261016-181121.sql`. `ADMIN_PASSWORD` moved from `[vars]` to a
Wrangler secret in the same rollout.

Migration `0020_paper1_bank_and_feedback.sql` (generated by `scripts/generate-paper1-seed.mjs`
from `Client_Feedback/Updated Paper 1 information-Oct2026`) hard-replaces Paper I and moves it
onto `/api/attempts`. Earlier drafts of this work (`0020_replace_paper1_bank`,
`0021_paper1_part_a_bands`, `0022_replace_paper1_bank_from_docx`) were applied only to local
databases and were squashed into this single migration before any production deploy.

It **deletes** Paper I attempts, answers, reports, PDF cache rows and class overviews for
`test_code='01'`, all `submissions`, and the old Paper I bank, dimensions and bands. It then:

- adds `question_groups.cefr_level`, `score_conversion_bands.level_label` and the
  `feedback_items` table, and drops `attempt_reports.ai_feedback_zh`;
- inserts 12 grammar dimensions, 90 groups and 2,640 variants (Part A 1,800, Part B 840),
  keeping the printed `TT-PP-SS-GGG-QQ` codes;
- inserts 1,869 preset feedback rows keyed `TT-PP-SS-GGG-QQ-AA`;
- inserts 21 Paper I bands: Part A /60 (8), Part B thresholds (5), and the overall CEFR ladder
  with IELTS/TOEFL (8).

Reports move to `rv3` variables: overall raw /90 with a percentage and ladder CEFR, Part A
area labels and missed-question feedback codes, Part B sequential placement. Reports are
English only, with no questions, answer keys, cohort or ranking. The PDF layout version is 9.

`/api/submit` is retired (410). Do not run `--remote` as a casual local command.

## v5.1 — Paper I feedback italics and word-list links (`0021`)

Migration `0021_paper1_feedback_formatting.sql` (same generator, non-destructive) updates 1,845
of the 1,869 `feedback_items` rows with inline markup taken from the Word files: `*italic*` for
italicised runs (grammar-point titles, example words, structures, book titles) and
`[text](url)` for the three Part B roadmap links — *the Oxford 3000* (A2), *the Oxford 5000* (B1)
and the *Academic Word List* (B2). No wording changes. The web report renders the markup with
`RichText`; the PDF uses Montserrat Italic / SemiBold Italic from R2 and clickable link
annotations (PDF layout version 10). Upload the two italic fonts with `upload-assets.ps1`.
